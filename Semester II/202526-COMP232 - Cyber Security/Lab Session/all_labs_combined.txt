In this lab session, you will learn about basic attacks on passwords, and password strength.
Passwords are stored in an encrypted form. This involves running an encryption algorithm on
the plain text password, and storing the output of the algorithm. A very popular algorithm for
encryption was the Secure Hash Algorithm 1 (SHA1), which computes a hash function. The
output of hash functions are typically called hash strings, or simply hash. The SHA1
algorithm has now been discontinued and more sophisticated ones have taken its place.
However, it is still a nice example to study.

2. Password-Based Encryption (PBE)
In the examples of programs given in the previous section, the keys used in encryption were
generated automatically without any user input. In many cases we would like to implement
password-based encryption.
Password-based encryption mechanisms in JCE are based on cryptographic hashing
mechanisms. In short, a password and a salt, which is a random data is fed into a mixing
--- Page 2 ---
function (a kind of hash function) which is applied iteratively the number of times defined by
iteration count. All this happens in the Secret Key Factory object. The result is used then to
create a key in the Cipher object. To decrypt one has to know the password (secret piece of
data), the salt and iteration count (these two are usually not considered as secret and may
be known to the attacker).

353513
ECB( Electronic CodeBook)
ECB uses the same key and encrypts/decrypts each block indepdently.
Not reccoemnded for large blocks.
Pros:
- Encryption Parellelitation: Different blocks can be encrypted and decrypted simultaneously.
This means that:
• It is faster
• If there is an error in the encryption of one block, this error does not affect other block encryptions.
Cons:
- Pattern preservation: Patterns in the plaintext will be transferred to the cipher text. Also, the same
simple text will be encrypted to the exact same cipher text.
This makes it vulnerable to attacks.
This is why it is only recommended for small blocks such as keys, to avoid pattern preservation
from the plaintext to the ciphertext.
CBC(Cipher Block Chaining):
CBC encrypts each block, by XORing the plaintext of the current block, with the ciphertext of the previous
block. This means that each new ciphertext block depends on all previously processed plaintext blocks.
-For the first plaintext block, an IV is used(Initialization Vector)
-Recommended for large blocks
Pros:
- No pattern preservation!
Cons:
- No encryption parallelization (But decryption can be parallelized!)
- An error in one ciphertext block can cause errors in all further blocks!
Th
CBC Encryption and Decryption process:
CBC Encryption:
- The plain text is XORed with the previous ciphertext(if this is the first plaintext block, XOR with the IV)
- The XORed plaintext is then encrypted using the key.
CBC Decryption:
- The ciphertext is decrypted using the key
- The plaintext produced is XORed with the previous ciphertext block

DES (The Data Encryption Standard): An outdated symmetric key encryption method

AES( Advanced Encryption Standard): The current encryption standard, used worldwide
- Key length: 128, 192 and 256. Far greater security than DES
- It operates of 128-bit blocks of data
- Sigingiciantly more secure thatn DES. Its adoption is widespread worldwide
- Faster than DES!
