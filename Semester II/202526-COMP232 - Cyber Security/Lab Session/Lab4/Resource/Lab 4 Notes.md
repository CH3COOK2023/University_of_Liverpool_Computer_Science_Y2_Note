## Diffie-Hellman 密钥交换 (DHKE) - 学生笔记

**概述：**

DHKE 是一种加密协议，允许双方在不安全的信道上建立共享密钥，是加密通信的基础。

**优点：**

- 无需预共享密钥即可安全地交换密钥。
- 具有抗窃听性，确保只有预定参与方能计算出共享密钥。

**缺点：**

- 除非结合身份验证方法，否则容易受到中间人攻击。

**应用场景：**

- 用于安全网页浏览的 HTTPS、用于加密网络访问的 VPN、安全电子邮件 (PGP) 以及远程访问 (SSH)。

**WhatsApp 示例：**

WhatsApp 使用包含 DHKE 的 Signal 协议进行端到端加密消息传输，仅允许通信用户访问消息内容。

**实践练习：**

1. Alice 和 Bob 协定公共参数。
2. 双方各自选择私有数字，计算并分享公共值。
3. 双方独立计算出相同的密钥。

- 本练习演示了安全通信的建立过程，突出了加密在现代数字交互中的作用。

------

### DHKeyAgreement2.java 说明：

此 Java 代码演示了 Alice 和 Bob 两方之间的 Diffie-Hellman 密钥交换。过程包括：

- **初始化：** Alice 和 Bob 根据 2048 位密钥长度生成各自的 DH 密钥对。
- **密钥协商过程：** 每一方使用其私钥初始化 `KeyAgreement` 对象并交换公钥。
- **共享密钥生成：** 利用对方的公钥，他们执行 DH 协议的第一阶段，生成仅两人知晓的共享密钥。
- **教学重点：** 本示例帮助学生掌握安全通信的关键概念，如公钥/私钥、密钥长度的重要性，以及如何在不直接交换的情况下获得对称加密密钥。

在 `DHKeyAgreement2.java` 中，重点是建立两方之间的共享密钥。为了进行实验，学生可以在初始化阶段修改密钥长度。通过尝试 1024、2048 和 4096 位等不同长度，学生可以观察密钥生成和完成交换过程所需时间的变化，从而理解安全性和性能之间的权衡。

------

### DHKeyAgreement3.java 说明：

此 Java 代码将 DHKE 协议扩展到了三方：Alice、Bob 和 Carol。

- 步骤与两方交换类似，增加了 Carol 作为第三名参与者。
- 每一方生成 DH 密钥对，并使用其私钥初始化 `KeyAgreement` 对象。
- 他们以轮询方式交换公钥，并利用这些公钥生成三方都能计算出的共享密钥。

对于 `DHKeyAgreement3.java` 文件，该脚本将密钥交换扩展至三方。与两方案例类似，修改 Alice、Bob 和 Carol 在密钥对生成时使用的密钥长度，可以深入了解多方密钥交换的复杂性和时间要求。再次强调，尝试不同的密钥长度有助于理解涉及多个参与者的安全通信协议的可扩展性和效率。
