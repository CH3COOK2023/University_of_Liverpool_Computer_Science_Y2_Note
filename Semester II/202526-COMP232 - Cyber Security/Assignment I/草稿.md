# Task B 暴力破解攻击时间估算

在本节中，我们假设攻击者已知除密码外的所有加密参数 ：

* 
**预定义的明文 (Predefined Plaintext)** 


* 
**生成的密文 (Resulting Ciphertext)** 


* 
**盐值 (Salt)** 


* 
**迭代次数 (Iteration Count)** 



基于T ask A 的实验数据，单次解密过程的平均耗时 为 $t=0.12\text{~ms}$。攻击者的目标是通过穷举密码空间来匹配已知的明文与密文 。

暴力破解所需的总时间取决于密码长度 ($L$) 和字符集空间 ($R$)。估算成功恢复密码的平均期望时间公式如下：

$$
T = \frac{R^L \times t}{2}
$$



* **$T$**：估算的平均破解时间。
* **$R$**：密码空间（字符集组合）。
* **$L$**：密码长度。
* **$t$**：单次解密耗时（取实验平均值 $0.12$ ms）。
* **因子 $1/2$**：基于统计学原理，攻击者通常在遍历 $50\%$ 的搜索空间时即可成功发现密码。



密码空间 (R) 的定义：为了覆盖不同的攻击场景，我们将可能的密码字符组合定义如下：

| 组合                | 密码空间 $R$ |
| ------------------- | ------------ |
| 小写                | 26           |
| 大写                | 26           |
| 数字                | 10           |
| 字符                | 33           |
| 小写+大写           | 52           |
| 小写+数字           | 36           |
| 小写+字符           | 59           |
| 大写+数字           | 36           |
| 大写+字符           | 59           |
| 数字+字符           | 43           |
| 小写+大写+数字      | 62           |
| 小写+大写+字符      | 85           |
| 小写+数字+字符      | 69           |
| 大写+数字+字符      | 69           |
| 小写+大写+数字+字符 | 95           |



在实际攻击中，破解者通常无法预知密码的精确组成，因此会采取递进式的尝试策略。对于包含复杂字符的密码（如 `P@S$W0rD`），攻击者可能会先尝试纯字母或纯数字的子集空间，在失败后再扩展至全字符集（$R=95$）。由于子集空间（如 $26^8$）在全集空间（$95^8$）的数量级面前几乎可以忽略不计，因此我们的估算将直接采用密码所属的**最小覆盖空间**作为计算基准。

根据实验 1 中提供的密码列表 ，在 $t = 0.12$ ms 的条件下，估算的破解时间如下表所示：

| 密码原文 (Password)    | 长度 ($L$) | 假定的组合空间 ($R$) | 预计平均耗时 (年)             |
| ---------------------- | ---------- | -------------------- | ----------------------------- |
| `P@S$W0rD`             | 8          | 全字符集 (95)        | $\approx 12622$               |
| `thisismypassword`     | 16         | 纯小写 (26)          | $\approx  8.2\times10^{10}$   |
| `VeryLongP@$$W0rD`     | 16         | 全字符集 (95)        | $\approx 8.37 \times 10^{19}$ |
| `%O^t#2Fv0JUjVdRV2RW%` | 20         | 全字符集 (95)        | $\approx 6.82 \times 10^{27}$ |



结论：结果表明，**密码长度 ($L$)** 是决定抗暴力破解强度的核心因素。即使 `thisismypassword` 的字符复杂度较低，但由于其长度达到 16 位，其安全性已远超 8 位的复杂字符密码。





# Task C 迭代次数对加解密时间的影响分析 

探究PBE中，攻击成本随迭代次数（Iteration Count）变化的规律 ：

* **测试范围**：迭代次数由 $1024$ 渐进增加至 $2048$。
* **采样频率**：针对每一个迭代点，程序执行 $1000$ 次加解密循环并取平均值。 $1000$ 次循环已足以在统计学意义上消除系统随机波动，清晰展现趋势。



通过对四个测试密码（Decryption A, B, C, D）的数据采集，我们得到了如图 1 至图 4 所示的分布图。

* **原始数据分布**（见图 1、图 2）：随着迭代次数的增加，所有密码的加解密耗时呈现出极其一致的上升趋势。
* **线性拟合分析**（见图 3、图 4）：利用最小二乘法对采样点进行一次函数拟合，得到如下解析式（以 Decryption A 为例）：

$$
y = (1.22 \times 10^{-4})x + (2.68 \times 10^{-3})
$$



【图片】

根据拟合图像及函数解析式，我们可以得出以下关键结论：

1. **高度线性相关性**：拟合直线的斜率 $a \approx 1.22 \times 10^{-4}$ 具有高度的一致性，证明了耗时 $y$ 与迭代次数 $x$ 之间存在严谨的线性正相关关系 。


2. **单位迭代成本**：斜率 $a$ 代表了每增加一次哈希迭代所带来的额外计算时间开销（约 $0.122 ~\mu s$）。这种开销是由底层算法（如 MD5）重复执行哈希运算产生的！
3. **截距项的含义**：截距 $b$（约 $0.00268 \text{~ms}$）代表了算法的固定初始化开销，包括内存分配、`Cipher` 对象实例化等。由于 $b \ll ax$，可以确认迭代运算是 PBE 性能损耗的绝对主导因素。



这种线性增长关系是**密钥拉伸（Key Stretching）**技术的理论基础。通过增加迭代次数，系统能够以对合法用户几乎无感的微小代价（如增加 $0.5 \text{~ms}$），强制性地将攻击者的总破解时间翻倍。这在面对Task B 中所讨论的巨大搜索空间时，能产生极强的防御增益。







# Task D 未知迭代次数下的攻击估算

在Task B中，我们假设攻击者已知迭代次数 $n=1024$，因此单次解密时间 $t$ 是一个固定的小常数（约 $0.12\text{~ms}$）。但在本变体中，攻击者虽掌握盐值、明文和密文，却**不知道迭代次数 $N$** 。

这意味着攻击者在暴力破解过程中，每尝试一个可能的密码，都必须**额外遍历**所有可能的迭代次数，直到生成的密文匹配为止 。

Task C 的拟合结果已经证明，解密时间 $t$ 与迭代次数 $n$ 呈线性关系：

$$
t(n) = a \cdot n + b
$$

其中 $a$（斜率）和 $b$（截距）为实验测得的常数。

当迭代次数未知时，尝试单个密码的总时间 $t$ 不再是 $t(1024)$，而是在可能范围 $[1, N_{max}]$ 内的**累加和**：

$$
t(N_{max}) = \sum_{n=1}^{N_{max}} (a \cdot n + b)
$$



利用等差数列求和公式，我们可以将上述公式展开：

$$
t(N_{max}) = a \cdot \frac{N_{max}(N_{max} + 1)}{2} + b \cdot N_{max}
$$
这意味着，当迭代次数未知时，攻击单个密码的时间复杂度从 $O(1)$ 变成了 **$O(N_{max}^2)$** 级别的增长（相对于迭代范围的上限）。

## 估算分析（示例）

原本解密一次`P@S$W0rD`只需要$t = 0.12\text{~ms}$，现在**参照 Task C 的拟合函数**结果，我们知道解密时间解析式
$$
t = 0.000122n + 0.00268
$$

> 此处带入 $n=1024$得到$t=0.1276 \text{~ms}$

此处 $a=0.000122$，$b=0.00268$，现在，如果未知迭代次数，我们需要假设合理的迭代次数上限 $N_{max} = 10,000$。

那么单次解密时间变为
$$
\begin{aligned}
t(N_{max}) &= a \cdot \frac{N_{max}(N_{max} + 1)}{2} + b \cdot N_{max}\\\\
t(10000)&=0.000122\times\frac{10000\times10001}{2}+0.00268\times10000
=6127.41
\end{aligned}
$$
时间从 $t=0.1276\text{~ms}$变为$t=6127.41\text{~ms}$，足足上升了将近4.8万倍！

对应的总体破解时间也会上升4.8万倍！

结论：未知迭代次数极大地增加了暴力破解的计算成本。在密码空间 $R^L$ 的基础上，攻击者被迫引入了第二个搜索维度。这证明了**隐藏算法参数**（如迭代次数）与提高参数数值本身同样重要！





# Task E 对比分析与差异解释

在本节中，我们将 Task B 测得的本地估算时间与行业公认的在线密码强度评估服务（如 Security.org）进行对比，以评估理论模型与现实攻击场景之间的差距 。

以下表格展示了基于本地单线程 CPU 执行环境（$t = 0.12\text{~ms}$）与专业安全评估工具之间的显著差异：

| 目标密码               | 本地估算破解时间 (Years)      | Security.org 估算时间              | 数量级差异     |
| ---------------------- | ----------------------------- | ---------------------------------- | -------------- |
| `P@S$W0rD`             | $\approx 1.26 \times 10^4$    | **8 Hours**                        | $\approx 10^7$ |
| `thisismypassword`     | $\approx 8.30 \times 10^{10}$ | $\approx 3 \times 10^3$ Years      | $\approx 10^7$ |
| `VeryLongP@$$W0rD`     | $\approx 8.37 \times 10^{19}$ | $\approx 1 \times 10^{12}$ Years   | $\approx 10^7$ |
| `%O^t#2Fv0JUjVdRV2RW%` | $\approx 6.82 \times 10^{27}$ | $\approx 4.2 \times 10^{19}$ Years | $\approx 10^8$ |

实验结果显示，本地估算时间普遍比在线工具慢 $10^7$ 至 $10^8$ 个数量级。这种巨大差异主要源于以下因素：

- 本地实验仅使用 Intel i9-12900H 的**单线程**进行线性计算。而专业攻击者会利用由数百个 GPU（显卡）组成的集群，甚至是专门设计的 ASIC 芯片进行并行攻击 。
- **吞吐量差异**：GPU 在处理哈希与加密运算时的吞吐量比 CPU 高出数万倍。这种并行处理能力可能能将原本需要“万年”的计算量压缩至“小时”级别。

此外，考虑数据泄漏。

* **已知泄露**：如 Lab 1 所证，`P@S$W0rD`和`thisismypassword`这两个常见密码早已出现在 [kaspersky](https://password.kaspersky.com/) 网站中显示已被泄露在数据库中 。


* **非暴力穷举**：在线工具（及黑客）通常优先运行**字典攻击**。如果密码在泄露库中，破解时间几乎为零，而不必经过 Task 2 中模拟的完整暴力穷举过程 。

除此之外，还有硬件的区别

* 针对 `PBEWithMD5AndDES` 算法中的哈希迭代过程，特定硬件（如 FPGA）可以进行深度流水线优化。这使得在 Task C 中观察到的迭代成本（$a \cdot n + b$）在专用硬件上被大幅削减，进一步拉低了破解时间上限。

## 结论

尽管本地单线程模拟得出的破解时间在数学上表现出极高的安全性，但在现实威胁模型中，必须考虑攻击者具备的多核并行算力和已有的泄露字典。实验证明，**增加迭代次数**与**使用长随机密码**依然是抵御高性能硬件破解的最有效防线。

```java
public static byte[] encode(String password, int iterationTime, byte[] salt, String text) throws Exception {
    SecretKey key = SecretKeyFactory.
            getInstance("PBEWithMD5AndDES").
            generateSecret(new PBEKeySpec(password.toCharArray(), salt, iterationTime));
    Cipher pbeCipher = Cipher.getInstance("PBEWithMD5AndDES");
    pbeCipher.init(Cipher.ENCRYPT_MODE, key, new PBEParameterSpec(salt, iterationTime));
    return pbeCipher.doFinal(text.getBytes());
}
public static byte[] decode(String password, int iterationTime, byte[] salt, byte[] cipherText) throws Exception {
    SecretKey key = SecretKeyFactory.
            getInstance("PBEWithMD5AndDES").
            generateSecret(new PBEKeySpec(password.toCharArray(), salt, iterationTime));
    Cipher pbeCipher = Cipher.getInstance("PBEWithMD5AndDES");
    pbeCipher.init(Cipher.DECRYPT_MODE, key, new PBEParameterSpec(salt, iterationTime));
    return pbeCipher.doFinal(cipherText);
}
```

```java
public static void calculateBruteForce(String label, int space, int length, double msPerAttempt) {
    BigInteger attempts = BigInteger.valueOf(space).pow(length);
    // search half space is possible to find out the password
    BigDecimal totalMs = new BigDecimal(attempts)
            .multiply(BigDecimal
                    .valueOf(msPerAttempt))
            .divide(BigDecimal.valueOf(2), RoundingMode.HALF_UP);
    BigDecimal days = totalMs.divide(BigDecimal.valueOf(86_400_000), 2, RoundingMode.HALF_UP);
    BigDecimal years = days.divide(BigDecimal.valueOf(365), 2, RoundingMode.HALF_UP);
    System.out.printf("Password info: %-30s | Length: %2d | Estimate Year : %s%n", label, length, years.toPlainString());
}
```

```java
            for (int k = 0; k < loopCount; k++)
                cipherText = encode(password, iter, salt, plainText);
            double avgEncryptTime = (System.nanoTime() - startEncryptTime) / (double) loopCount / 1_000_000.0;
            
            // decrypt time
            long startDecrypt = System.nanoTime();
            for (int k = 0; k < loopCount; k++) decode(password, iter, salt, cipherText);
            double avgDecryptTime = (System.nanoTime() - startDecrypt) / (double) loopCount / 1_000_000.0;
            
            // total time
            br.write(String.format("(%.5f,%.5f)",avgEncryptTime,avgDecryptTime));
            if(i!=passwordList.length-1)
                br.write(",");
        }
        System.out.println("Iter = " +iter);
        br.newLine();
        br.flush();
    }
    br.close();
}
```
