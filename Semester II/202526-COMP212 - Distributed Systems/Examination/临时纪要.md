# COMP212 考前速查

## 网络与通信
| 协议 | 层 |
|------|------|
| IP | Network |
| TCP | Transport |
| HTTP, FTP | Application |

| | TCP | UDP |
|------|------|------|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠（慢） | 不可靠（快） |
| 用途 | HTTP, POP, IMAP | DNS, 流媒体, VoIP |

- **Socket**: 双向通信端点，绑定端口号
- **HTTP**: 超文本传输，client-server，基于TCP；HTTPS = 加密版
- **RPC**: 远程过程调用，10步（client stub ↔ server stub），透明如本地调用
- **RMI**: Java 远程方法调用，9步（Interface → Server → Client → javac → rmiregistry → 启动）

## 通信模式
| | 瞬时 | 持久 |
|------|------|------|
| 异步 | 双方在线，发完不管 | 不在线也可，消息存队列 |
| 同步 | 双方在线，发完等回复 | 不在线也可，发完等 |

- **MOM**: 消息队列中间件，支持持久异步通信
- **Message Broker**: 转换不同格式（老系统 ↔ 新系统）

## 流媒体
- **Jitter 缓解**: ① Buffering ② 交错打包（连续帧分散到不同包）

## 进程与服务器
| | Stateless | Stateful |
|------|------|------|
| 含义 | 不记连接信息 | 维护连接状态 |
| 例子 | Web, DNS | 文件服务器 |
| 特点 | 简单，挂了换就行 | 效率高，挂了丢状态 |

- **Desktop Virtualisation**: Guest OS 作为 Host OS 的进程运行（如 VirtualBox）

## 命名与 DNS
- **DNS 功能**: 域名→IP, MX记录(邮件), 反向解析, Host信息, Well-known服务
- **Iterative**: client 逐个问；**Recursive**: server 替 client 爬链
- 跨国查询用 Recursive（省长途传输）
- DNS 运行在应用层，用 UDP 端口 53

## 时钟同步
| 算法 | 类型 | 要点 |
|------|------|------|
| Cristian | 中心化 | UTC服务器 + (T1-T0)/2，不能往回拨（减速等追上） |
| Berkeley | 中心化 | Master轮询→算平均→广播调整量 |
| Lamport | 逻辑时钟 | 不需要真实时间，happened-before + 消息时间戳 |

- **Clock Skew**: 晶振误差累积，一次校准不够，需持续同步

## 事务（Transactions）
- **ACID**: Atomic(全或无), Consistent(不变量), Isolated(串行化等价), Durable(提交即永存)
- **Flat**: 简单但太刚性
- **Nested**: 父子事务，子提交后父abort→违反Atomicity
- **Private Workspace**: 未提交前读写都在私有副本
- **Writeahead Log**: 先写日志再改文件，abort时用日志回滚

## 互斥（Mutual Exclusion）
```
程序4段: Entry → Critical → Exit → Remainder
互斥算法只管 Entry + Exit
```
- **Centralised**: 单一协调者（简单，单点故障）
- **Distributed**: 组内协商

## 复制（Replication）
- **目的**: 可靠性（一个挂了另一个顶上）+ 性能（数据近用户）
- **Seq Consistency**: 所有进程看到相同的操作交错顺序
- **Push**: 服务端主动推 → 高一致性
- **Pull**: 客户端按需取 → 浏览器缓存
- **Hybrid (Leases)**: Push一段 + 到期变Pull

## 容错
### 故障类型
| 按频率 | 例子 |
|------|------|
| Transient | 鸟飞过微波束 |
| Intermittent | 接口接触不良 |
| Permanent | 芯片烧毁、软件bug |

| 按表现 |  |
|------|------|
| Crash | 正常干活，然后停 |
| Byzantine | 任意异常（更难处理） |

### 冗余
| 类型 | 手段 | 例子 |
|------|------|------|
| Information | 加额外位 | 校验位, Hamming码 |
| Time | 重做 | 事务 ABORT→RETRY |
| Physical | 加硬件/软件副本 | Replication |

### 恢复
| | 方向 | 成本 | 缺点 |
|------|------|------|------|
| Backward | ← checkpoint回滚 | 快照开销 | 不能回滚的操作无解 |
| Forward | → 从错误状态修到正确 | 需穷举故障 | 未知错误无法处理 |

## 安全

|------|------|------|
| 密钥 | 同钥加密解密 | 公钥加密，私钥解密 |
| RSA | — | 基于大素数分解，若素数分解被攻破则失效 |

## 分布式算法复杂度
| 算法 | 时间 | 通信 |
|------|------|------|
| Spanning Tree Broadcast | d (深度) ≤ n-1 | n-1 条消息 |
| Broadcast + 构建BFS树 | O(D) - 网络直径 | O(m) m是边数 |
| LCR (环选举) | n+1 | Θ(n²) 最坏 |
| FloodMax (选举) | D+1 | D·m |
| FloodSet (共识) | f+1 f是允许最大宕机处理器 | O((f+1)n²) |

## 不可能性结论
- 全同处理器在环上无法选举
- 消息无限丢失 → 共识不可能（Coordinated Attack）
